# Dehaze adjustment

Related roadmap: Phase G / PDF section 16. Related workflow: `INCREMENTAL_WORKFLOW.md` sections 4 and 5.1.
Related prior slices: docs/planning/implementation-notes/2026-09-30-texture.md,
docs/planning/implementation-notes/2026-10-12-clarity.md.

## 1. Problem, goal, and non-goals

Texture (medium-scale detail) and Clarity (broad local/midtone contrast) are
implemented, but PhotoEdit still has no haze/atmospheric-veil control. This
slice adds one neutral-by-default Dehaze control. Unlike Texture and
Clarity -- both signed-residual/unsharp local-contrast tricks that differ
only by blur scale -- Dehaze is a genuinely different operation: a
lightweight approximation of Lightroom's dark-channel-style haze removal,
not another local-contrast trick at a third scale. It does not add
Vignette, Grain, sharpening, or noise reduction. It is not a
physically-accurate atmospheric scattering model, only an approximation.

## 2. Current behavior

`ToolsPanel` emits flat basic adjustments; `ImageController` owns normalized
state and coordinates preview/final rendering; `ProcessingRequest` and
`ProcessingWorker` carry category dictionaries; `CombinedAdjustmentCommand`
provides the synchronous undo fallback. Clarity is currently the final
pipeline stage, applied right after Texture (which runs right after Color
Grading).

## 3. Design and flow

Add a third -100..100 Dehaze slider to the existing Effects section,
directly below Clarity. Dehaze remains a top-level persisted float for
consistency with other single-slider controls, while processing APIs carry
`{"dehaze": value}` as a separate category, following Texture/Clarity's
wiring pattern exactly. The controller sends it through preview, final,
synchronous, restore, export, reset, and history paths. The worker applies
it after Clarity and includes it in preview cache signatures. Pipeline
order is now ... Color Grading -> Texture -> Clarity -> Dehaze -> ... .

`DehazeProcessor` estimates a per-pixel haze veil as the minimum across RGB
channels (a dark-channel/airlight approximation), lightly blurs that
estimate with a Gaussian (`sigma=15`, reflected borders) to approximate a
transmission map, and for positive values (remove haze) subtracts a
fraction of the veil while rescaling to restore overall level:
`result = (source - strength * veil) / max(1 - strength * 0.9, 1e-3)`. For
negative values (add haze/fog, which Lightroom's single -100..100 Dehaze
slider also supports) it blends toward a light gray haze color
(`0.85`) proportional to the magnitude:
`result = source + strength * (0.85 - source)`. It operates on float32
linear-light data and deliberately does not clip intermediate values,
preserving HDR headroom. Zero returns immediately.

The scale and operation are both deliberately distinct from Texture
(`sigma=2`, signed residual) and Clarity (`sigma=20`, signed residual):
Dehaze blurs a single-channel minimum-across-channels veil estimate rather
than the full image, and combines it with a rescaling division rather than
an additive residual -- the same "distinct scales/semantics" requirement
flagged when Clarity was added (clarity note section 5) applies here too,
but Dehaze goes further and uses a different formula shape entirely.

## 4. Contracts and compatibility

- State key: `dehaze`, finite numeric float, default `0.0`.
- UI and processor range: `-100..100`; processor clamps out-of-range callers.
- Older payloads that omit the key restore as zero.
- No schema-version bump is needed because this is an additive defaulted key.
- No dependency is added; NumPy and existing OpenCV are sufficient.

## 5. Nuances and failure modes

Constant/neutral images must not develop a color cast: because the veil
(or haze blend) is computed and applied identically across all three
channels, a constant input stays channel-equal after processing, even
though its overall level may shift (that shift is the intended dehaze/fog
effect). 1x1 images must not fail -- the Gaussian blur on a single-channel
minimum works the same way Texture/Clarity's full-image blur does on tiny
inputs, via OpenCV's border padding. Output shape/dtype must be retained.
Reflect borders avoid a dark artificial frame at the veil estimate's edges.
The rescaling denominator is bounded away from zero (minimum `1e-3`) so a
strength near the extreme end cannot divide by (near-)zero. The effect is
intentionally an approximation, not a claim of Lightroom-identical math.

## 6. UI/reskin, dependencies, and performance

The view contains only the slider and emits plain data; all math stays in
the processor. Existing throttling, cancellation, interactive proxies,
quality preview, and delayed full-resolution rendering remain unchanged.
The dark-channel estimate is a single-channel reduction before the
Gaussian blur, so it costs about the same as Texture/Clarity's blur despite
operating at a larger sigma (15 vs. Texture's 2, below Clarity's 20) --
not observed to be a bottleneck in the automated suite. Any later Phase G
slices (Vignette, Grain, sharpening, noise reduction) must continue to use
distinct scales/semantics from Texture, Clarity, and Dehaze.

## 7. Test plan and manual smoke

Automated coverage pins identity/copy behavior at zero, positive dehaze
reducing a synthetic haze veil relative to its hazy input, negative values
adding haze (lower contrast, higher mean), constants/neutrals staying
channel-equal in both directions, dtype/shape/headroom, parameter clamping
in both directions, tiny images, a sigma-distinctness check against
Texture/Clarity, UI range/emission/restore, queue and worker propagation/
skip behavior, controller persistence/export, and command undo -- mirroring
Texture/Clarity's test structure file-for-file. Run the complete suite.

Manual: open a hazy image; move Dehaze positive and negative; verify a
responsive preview, final render on release, undo/redo, reset, image-switch
restore, and export, with Texture, Clarity, and Dehaze active together.

## 8. Rollout, rollback, and acceptance

The feature is additive and identity-defaulted. A plain revert removes it;
older builds ignore the extra persisted key. Acceptance requires the full
vertical path, no UI-thread image math, backward-compatible restore, passing
targeted/full tests, clean diff checks, and honest manual-test reporting.

Plan approved -- implementation allowed: mirrors the approved Texture/
Clarity slices' scope and wiring pattern (2026-10-12).

## 9. Implementation summary

Implemented `DehazeProcessor` (dark-channel/veil-removal approximation,
sigma=15.0, distinct formula shape from Texture/Clarity's signed-residual
approach) and wired it through every integration point Clarity touches:
`ImageController` (defaults, processor/params state, preview/final/sync
rendering, export, restore/export state, reset, `apply_adjustments`, the
four `on_*_changed` debounced paths, slider-release,
`_has_pending_adjustment_changes`, delayed final render, and
`commit_adjustments`), `ProcessingRequest`/`ProcessingQueue`,
`ProcessingWorker` (processor, submit/apply/cache-key/signature,
perf logging), `CombinedAdjustmentCommand`'s synchronous fallback, and a
third "Dehaze" slider in `ToolsPanel`'s Effects section below Clarity.
Dehaze is applied immediately after Clarity everywhere in the pipeline.
No unrelated code was touched; the roadmap coverage table and git history
are left for the calling session.

One implementation adjustment from the initial sketch: the dark-channel
veil estimate is computed as a 2-D single-channel array (`np.min(source,
axis=-1)`) and re-expanded with `[..., np.newaxis]` only after the Gaussian
blur, rather than kept 3-D (`keepdims=True`) throughout -- `cv2.GaussianBlur`
drops a trailing size-1 channel axis, so blurring a `(H, W, 1)` array
produces a `(H, W)` result that fails to broadcast against the `(H, W, 3)`
source without that explicit re-expansion.

Verification: targeted new/changed tests (processor + controller + command
+ queue + worker + tools-panel Dehaze tests) **16 passed**; complete suite
**656 passed, 1 deselected in 112.66s** (the pre-existing
`test_geometry_is_restored_on_next_launch` offscreen flake noted in the
Texture/Clarity notes persists and was deselected, not fixed, per the task
instructions). A live GUI smoke test was not performed in this
non-interactive environment.
