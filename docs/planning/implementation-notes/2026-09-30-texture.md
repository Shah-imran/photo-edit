# Texture adjustment

Related roadmap: Phase G / PDF section 16. Related workflow: `INCREMENTAL_WORKFLOW.md` sections 4 and 5.1.

## 1. Problem, goal, and non-goals

PhotoEdit completes Color Grading but has no Effects controls. This slice adds
one neutral-by-default Texture control that enhances or softens medium-scale
detail. It does not add Clarity, Dehaze, Vignette, Grain, sharpening, noise
reduction, masking, or proprietary Adobe processing.

## 2. Current behavior

`ToolsPanel` emits flat basic adjustments; `ImageController` owns normalized
state and coordinates preview/final rendering; `ProcessingRequest` and
`ProcessingWorker` carry category dictionaries; `CombinedAdjustmentCommand`
provides the synchronous undo fallback. Color Grading is currently the final
pipeline stage.

## 3. Design and flow

Add an Effects section after Color Grading with a -100..100 Texture slider.
Texture remains a top-level persisted float for consistency with other
single-slider controls, while processing APIs carry `{"texture": value}` as a
separate category. The controller sends it through preview, final, synchronous,
restore, export, reset, and history paths. The worker applies it after Color
Grading and includes it in preview cache signatures.

`TextureProcessor` computes a Gaussian base (`sigma=2`, reflected borders),
forms the signed residual `source - base`, and adds up to 75% of that residual.
Positive values enhance the residual; negative values move toward the base.
It operates per channel on float32 linear-light data and deliberately does not
clip intermediate values, preserving HDR headroom. Zero returns immediately.

## 4. Contracts and compatibility

- State key: `texture`, finite numeric float, default `0.0`.
- UI and processor range: `-100..100`; processor clamps out-of-range callers.
- Older version-1 payloads omit the key and restore as zero.
- No schema-version bump is needed because this is an additive defaulted key.
- No dependency is added; NumPy and existing OpenCV are sufficient.

## 5. Nuances and failure modes

Constant images must remain constant, neutral RGB must stay neutral, 1x1 images
must not fail, and output shape/dtype must be retained. Reflect borders avoid a
dark artificial frame. Applying the same signed residual per RGB channel avoids
inventing color in neutral pixels. The effect is intentionally an approximation,
not a claim of Lightroom-identical math.

## 6. UI/reskin, dependencies, and performance

The view contains only the slider and emits plain data; all math stays in the
processor. Existing throttling, cancellation, interactive proxies, quality
preview, and delayed full-resolution rendering remain unchanged. Gaussian blur
is linear-time and runs only off the UI thread during normal use. Phase G's
later Clarity and sharpening slices must use distinct scales/semantics.

## 7. Test plan and manual smoke

Automated coverage pins identity/copy behavior, positive enhancement, negative
softening, constants/neutrals, dtype/shape/headroom, parameter clamping, tiny
images, UI range/emission/restore, queue and worker propagation/skip behavior,
controller persistence/export, and command undo. Run the complete suite.

Manual: open a detailed image; move Texture positive and negative; verify a
responsive preview, final render on release, undo/redo, reset, image-switch
restore, and export.

## 8. Rollout, rollback, and acceptance

The feature is additive and identity-defaulted. A plain revert removes it;
older builds ignore the extra persisted key. Acceptance requires the full
vertical path, no UI-thread image math, backward-compatible restore, passing
targeted/full tests, clean diff checks, and honest manual-test reporting.
